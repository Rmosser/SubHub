# 「配置与场景」页 v3 规格

只读的配置对照图：左边手机栈，右边阅读栏（原文）。数据表在本目录，由 `_gen.py` 从 `design/client-ui-replica/inventory/*.json` 生成并校验（`label` 直接取自 inventory，行号对不上会报错）。

| 文件 | 屏 | 行 | 带 todo 的行 | 纸条 | 本机覆写 |
|---|---|---|---|---|---|
| `surge.json` | 22 | 64 | 10 | 3 | 0 |
| `shadowrocket.json` | 18（含补的 `config-script`、缓做的 2 个选择器） | 43 | 11 | 1 | 0 |
| `clash-mi.json` | 11（含补的 `core-override`） | 32 | 2 | 1 | 31 |

另有屏级 todo：Surge 4、Shadowrocket 3、Clash Mi 5（写在 `screens[].todo`）。

## 1. 页面

- 顶部：Surge / Mihomo / Shadowrocket 分段切换。设备选择在旁边；只有一台设备时是纯文字。
- 没有输入框、保存按钮、场景管理、能力分组。
- 取数：`render-preview?target=…` 的 `content`、`revision`，以及栏头生成提示用的 `blockers` 和 `diagnostics`。按 `revision` 缓存，切换客户端不重拉。
- 深链：`target`、设备 id、屏 id、行 id 写进 URL。不放 token，不放打码的值。
- 切换客户端：换成那一端的 `root`，清空选中。

## 2. 手机栈

- 栈列定宽 = 手机宽 + 3 条露边（每条 15 pt × 缩放），三端一样，切换客户端不位移。最前面的手机靠右，露边向左长。
- 层级：每退后一级缩到 1 / .955 / .912 / .872、蒙一层 0 / .38 / .54 / .66 的纱，再往后淡出。层级过渡只动 `transform` 和 `opacity`，420 ms，`cubic-bezier(.32,.72,0,1)`，不用 `filter` / `backdrop-filter`（背后的玻璃每帧都在画）；控件悬停态可用 `filter: brightness()`。
- 推入：新一级从右侧 30 pt 处滑入，不压到阅读栏；`kind` 为模态的屏从下 64 pt 升起。点露边返回到那一级，悬停露边显示那一级的标题。
- 根有多个时（`roots`）：Surge 是首页的三个分段，Shadowrocket 是底部两个 tab。它们互为平级，切换不算推入。
- 屏内位置（屏 / 行 / 条目）用 `replaceState` 写回 URL，不经路由，推入时不重渲染整页；推入、选中的回调排在下一帧之后。
- 版式按真机：
  - 列表屏：iOS 分组列表，度量取自 `replica/kit.css`。
  - Surge 首页三个分段：一组一张卡片。组头是卡片标题（带该功能的颜色和图标），开关行并进标题栏，组脚是卡片说明，按钮行是右下角的胶囊，分段行是勾选列表，「更多设置」是卡片下方居中的链接。顶部是配置名、「启动」和下划线分段，底部是悬浮 Tab 栏。
  - Clash Mi 首页：连接卡（状态点 + 开关、三段选择、我的配置）和设置卡（每行前置图标）。
  - Shadowrocket 首页与配置 tab：行首图标；节点行用圆形国旗，没有国旗时画地球。
  - 尺寸、颜色从 `screens/` 的真机截图量出，写在 `phone.css`，注释里记着量的是哪张截图。
- 三种行：
  - **写入行**：满墨色，显示从原文解析出的真实值，行底有微光。
  - **其余行**：墨色约 70%，悬停、焦点、选中时满墨；不显示值，开关画中性态，分段和勾选不画选中。Surge 卡片标题保持原色，只淡化开关。
  - **前提行**：其余行的样子，加纸角。见 `paper.md`。
- 画出来的都能点：行（含卡片标题栏、胶囊、勾选行、三段选择）和外壳控件（「启动」、配置名、Tab 栏、导航栏的 ✓ / + / 扫码、工具条）都有悬停和焦点态、`role` 和可访问名称。
  - 能切根的 Tab 和分段照旧切换；有下一级的推入；其余点了选中，阅读栏给一句说明。
  - 外壳没有原文对应：不画连线、不开段，说明叠在阅读栏顶部。说明写在 `about/<app>.json` 的 `@…` 键里（`@控件@屏` 优先于 `@控件`）。
  - 生成时，任何画出来的行或外壳控件既没有 `explain` 也没有 `about`，`build_readmap.py` 报错退出。
- 键盘：推入后焦点移到新一屏的返回键（没有就首行），返回后还给来时那一行。Esc 在页面任意处（不在输入控件里、没有打开的弹层时）返回上一级。
- 过渡中再点：按下那一拍（约 90 ms，新屏还没出发）里的第二下丢掉（当作双击）；滑动中点在正离开的屏上也丢掉；点在正到来的屏上排队，只留最后一次，过渡结束时仍落在最前一屏才执行。系统切到「减少动态效果」时，正在跑的过渡（含按下那一拍）立刻落定，之后的推入、返回没有动画。时序在 `transit.ts`，有单测。
- 切根（Surge 首页分段、Shadowrocket 底部 tab）：同时放下选中，解读和 URL 里的 `r` 一起清掉。页面只认最前一屏上的选中。
- 换设备或换客户端：选中、展开的段和焦点行在同一次渲染里清空，旧的屏 / 行 / 条目不再写回 URL。
- 导航行的弱光由子树推出：子树里有 `bind` 成立的写入行就亮。
- 列表屏（`bind.kind = list`）：模板行按原文逐条重复；`drop` 里的 inventory 样例行删掉；没有条目时显示 inventory 原来的占位行。长列表只渲染选中项前后约 50 条。
- 详情屏（`bind.kind = item`）：显示父列表里当前选中那一条。入口是列表行，不是导航栏的「+」；「+」照画，点了选中并说明它在手机上做什么。
- 选中：选中行满墨并提亮（原本淡化的行也一样），同屏其余满墨行退到一半；淡化行不再叠加退焦。外壳控件选中时是暖色光晕。不描边。

## 3. 阅读栏

- 就是原文，按段组织：INI 按 `[段]`，YAML 按顶层键。YAML 连续的顶层标量并成一个无头块，常开。
- 文件头连续的整行注释并成一个默认折叠的块（显示首行和行数），不占段头；里面有亮起或聚焦的行时自动展开。
- 段头：这一段的全部绑定行都落在同一个落脚屏时，用那个屏的手机标签加条数；否则用原名（`[General]`、`dns`）。这条由数据算出，不手工标。
- 一次只展开一段，展开的段占满剩余高度、段内滚动。其余段头吸附在栏顶和栏底。默认全部折叠。展开、收起按像素高度过渡 380 ms，高度单调变化；减少动态效果时立即。
- 整栏是定高行的虚拟列表：等宽、不折行、超长截断，点一行才折行。
- 被某个 `bind` 命中的行可点、有光；其余行不亮、不可点。注释行（`#` 开头）照常显示，不计入条数。
- 键盘：段头可聚焦，Enter / 空格展开或收起，焦点留在段头。可点的原文行用 roving tabindex：Tab 只进一次，↑ / ↓ / Home / End 在可点行之间移动，Enter / 空格触发。
- 栏头：生成提示按类型合并，入口是「N 类提示」（刻蚀文字加小纸角，可访问名称带总条数）。
  - 弹层是玻璃底、纸色左边线；每类一行加条数，点开看一句说明和明细（最多 40 条，其余「还有 N 条」）。
  - 常见类型改写成中文，未知类型照原文显示。排序：没写进配置的在前，待核对、降级、说明在后。规则在 `warningGroups.ts`，有单测。
  - `role="dialog"`；打开时焦点进入，Esc、点外部或 Tab 走出时关闭，焦点还给入口。
- 初版没有搜索（已知缺口）。

## 4. 联动

| 动作 | 结果 |
|---|---|
| 点段头 | 展开或收起；一对一的段同时把手机推到落脚屏，不选中行 |
| 点手机叶子行 | 展开所在段，滚到对应行，连线接到行 |
| 点手机导航行 | 推入下一级；对应段头亮，不展开 |
| 点原文里可点的行 | 手机推到那一屏并选中那一行；一行对应多个手机行时取数据表里靠前的那个 |
| 连线终点 | 段展开接到行；折叠接到段头；行滚出可视区时贴段的上沿或下沿 |

## 5. 解读（explain）

- 只在选中时出现，一两句话，说清手机上这个控件是干什么的。
- 来源按顺序取：
  1. 前提行用 `paper`（纸色）。
  2. 数据表的 `explain`；行亮着时，后面跟着跳到前提行的纸条链接。
  3. 否则用 `about/<app>.json` 的 `about`（控件作用），后面接一句它在哪：「只在手机上设置，配置里没有它。」「配置里没有这一项，App 用默认值。」或「这份配置没有写这一项，App 用默认值。」
- 有原文行的：解读插在亮起的原文行下方，撑开一条缝，原文不被遮挡。没有原文行的（含外壳说明）：解读叠在阅读栏顶部，不画连线，左边线发光；阅读栏顶部留出与它等高的可滚空间，并同时滚过这段高度，所以选中时原文一动不动；被盖住的行向上滚就露出来，键盘焦点也落在它下方（`scroll-padding`）。
- `override: true` 的行：只有原文里确实有那个键（`bind` 成立）时才能选中并显示 explain。
- 不用 inventory 的 `note`。

## 6. 空状态

- 409：手机树可浏览，全部无光、无值；阅读栏换成 blocker 列表（`detail.warnings`），纸色。

## 8. 宽度

- 并排时手机缩放由可视高度决定：`S = min(.9, (可视高度 − 26) / 874)`，下限 12/17（17pt 正文不小于 12px）；窗口再矮也不再缩小，整页纵向滚动。阅读栏不足 360px 时同样只缩到这个下限，仍放不下就改上下排。
- 手机栈和阅读栏之间留 32px，阅读栏封顶 880px，整组居中。
- 舞台宽度（不是视口）不足 760px 时改成上下排：手机在上，按宽度缩放，上限 .9，下限尽量保证 17pt 字不小于约 12px（S ≥ 12/17）；原文在下。选中后把解读滚进视野（离窗口底边留 25vh，`scroll-margin`；为它展开的段折叠动画结束后再校一次），选中状态保留。

## 9. 数据表结构

顶层：`client`、`target`、`format`（`ini` / `yaml`）、`root`、`roots`、`screens`、`rows`。

`screens[]`：`id`、`title`、`parent`、`via`（从父屏哪一行进来；`segment:…` / `tab:…` 表示平级切换；`null` 表示还缺入口行）、`depth`、`kind`、`rows`（本屏绑定行数）、可选 `deferred`、`todo`。

`rows[]`：`row`（`<屏>#<组>.<行>`，inventory 原始下标）、`label`、`bind`、可选 `explain`、`paper`、`override`、`drop`、`fixed`、`todo`。

### bind 的定位字段

| 字段 | 含义 |
|---|---|
| `ini` | 段名；可以是数组（任一段存在即成立） |
| `key` | 段内 `key = value` 的键；可以是数组（任一存在即成立） |
| `yaml` | 点分路径，如 `dns.enable` |
| `match` | 正则，只取段内匹配的行 |
| `re` | 对取到的值再做正则；有捕获组取第 1 组，`exists` 时表示「匹配才成立」 |
| `split` | 把单值按这个分隔符拆成多项（`list` 逐项成行，`count` 数项数） |

### 五种 kind

- `value`：单值。开关行按 `true` / `1` / `on` 为开。`map` 把原文值换成手机文案。
- `count`：段内非空非注释行数；带 `key` + `split` 时数项数；`yaml` 时数列表或映射的条数。
- `exists`：段或键是否存在。纸条行的 `bind` 是出现条件，不是值。
- `list`：屏内模板行逐条重复。
- `item`：详情屏的行，取当前选中那一条的某一部分。

### 行的两种语法（`list` / `item` 用）

1. **分隔列**：`sep` 取 `" "`、`","`、`"="`。`col` / `label_col` / `sub_col` / `value_col` 是列下标，可以是数组（拼起来显示）。`max_cols` 限制拆分次数，最后一列吃掉余下部分。`param: "k"` 取列里形如 `k=v` 的值。`unquote` 去掉首尾引号。
2. **`line: "kv-list"`**：形如 `名字 = a, b, c, k=v, …`（`[Proxy]`、`[Proxy Group]`、`[Script]`）。只在第一个 `=` 处切出名字。`part: "name"` 取名字；`pos: N` 取右边第 N 个不带 `=` 的字段；`param: "k"` 取 `k=v` 的值；`pos_from` + `repeat` 取从第 N 个起的全部位置字段，各成一行。`list` 用 `label_part` / `sub_pos`。

这两种语法、`map`、`re`、`mask`、`drop`、`fixed`、`roots` 是我在你给的结构上加的；五种 kind 没变。

### 没绑的

- Shadowrocket `config-general#5.6`、`#6.3` 是列表末尾的「添加」占位行，写在 `unbound_placeholders`，照画成灰行。
- 三端里标为「还没核对」的行（如 Shadowrocket 节点的流控、TLS、传输方式）一律不绑，灰显。SubHub 实际会写其中一些参数，它们在原文里不亮。
