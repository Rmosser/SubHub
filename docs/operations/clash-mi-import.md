# Clash Mi 导入与更新

证据基线：Clash Mi 1.0.31（内核 1.19.32），2026-11 实验台 E-M-008/151/153/154/166；SubHub 输出最低 Mihomo 1.19.28。

1. 打开设备当前场景的 Clash 链接，在「添加配置链接」中先关闭「启用备用下载通道」，再保存。每次新增都默认打开此开关，订阅地址可能包含令牌，经第三方中转会扩大地址暴露范围。
2. 核心覆写选择「内置-不覆写」。默认的「内置-覆写」会替换订阅整段 DNS，改变 SubHub 的 DNS 路径。
3. 添加成功后，在「我的配置」点选它作为当前配置。新增不会自动切换；连接时点选另一份配置会立即切换并生效。
4. 使用「规则」模式。更新当前配置只更新文件；需要断开再连接，内核和 providers 才按新配置加载。provider 固定缓存路径保留最近成功内容，URL 的 rev 变化不保证立即重新下载，更新间隔为 1800 秒。
5. 在「运行时配置」核对 DNS、TUN、IPv6。应用的「核心设置 → IPv6」优先于订阅；需要 IPv6 节点时设为「不覆写」或「启用」。只下发 IPv6 地址的节点在禁用 IPv6 时不可用。

`profile-title` 响应头使用由稳定哈希生成、不含设备私密名称的公开场景别名；非 ASCII 标题采用 `base64:` 加 UTF-8 Base64。链接中的 `name` 参数优先于此响应头。

若组为空，SubHub 使用 `empty-fallback: REJECT` 拒绝该组流量。若运行时出现 `COMPATIBLE`，请检查是否用了旧配置、旧内核或应用覆写；不要把它当作可用节点。
